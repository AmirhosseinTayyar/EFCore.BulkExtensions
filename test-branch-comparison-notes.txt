2. UpsertWithOnUpdateNonPK (SqlServer)
   master: PASS  |  refactor/clean: FAIL
--------------------------------------------------------------------------------

Test: Insert Customer "Kayle", then BulkInsertOrUpdate John/Smith/Kayle using
      UpdateByProperties = Name and SetOutputIdentity = true.

refactor/clean error:
  Assert.Equal() Failure: Expected 1, Actual 0  (customers[2].Id for "Kayle")

Why it differs:
  - On master, Id assertions run ONLY inside `if (sqlType == SqlType.Sqlite)`.
    SqlServer never asserts output identities, so the test passes without checking.
  - On refactor/clean, assertions were moved outside the Sqlite block and now
    run for SqlServer too:

      Assert.Equal(2, customers[0].Id);
      Assert.Equal(3, customers[1].Id);
  - SetOutputIdentity does not populate customers[2].Id after upsert on SqlServer
    (Actual: 0), exposing behavior that was previously untested on master.

Conclusion: Caused by a test-code change on refactor/clean (new SqlServer
            assertions) plus possible bulk SetOutputIdentity behavior on upsert.
            Not purely a Testcontainers issue.
